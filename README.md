# iLab

<!-- badges: start -->

<!-- badges: end -->

This package contains functions used to to process data for DBCA’s
iLab-Fish team. Most functions are specific for iLab-Fish processes and
are commonly used in code found in [Essential
scripts](https://github.com/iLab-fish/essential-scripts).

Please report any issues or requests for additional functionality to the
iLab-Fish technical team or via the [issues
tab](https://github.com/iLab-fish/iLab/issues).

## Installation

You can install the development version of iLab from
[GitHub](https://github.com/) using either:

``` r
remotes::install_github("iLab-fish/iLab")
# or
pacman::p_load_current_gh(char = "iLab-fish/iLab")
```

## Functions

Scripts for each function are stored in the `R` folder and create
associated `.Rd` documentation stored in `man`. External functions can
be called when `iLab` package is loaded or via `::` (e.g.,
`iLab::get_dir()`), internal functions can only be called via `:::`
(e.g., `iLab:::make_absolute()`)

| Function | Description | External | Notes |
|----|----|----|----|
| `check_structure()` | Validate campaign file/folder structure against standard template | Yes | Uses the internal function |
| `get_dir()` | Automatic location of (usually) DBCA sharepoint file pathways | Yes | Very useful for making reproducible scripts that access DBCA sharepoint data synced to users computers |
| `make_campaign_dir()` | Creates/updates iLab-Fish campaign directory structure based on standardised format | Yes | Inputs either user provided or interactive |
| `make_datasheet()` | Create a formatted fish analysis datasheet based on standardised field metadata | Yes | Uses the internal functions `analysis_cols()` and `make_absolute()` |
| `na_cols()` | Identify columns where some of all values are NA | Yes | Useful helper function for error testing |
| `ref_library()` | Shiny species ID guide based on images in `Asset-Fish/Science Communication/Cool Clips` | Yes | Proof of concept. Relies on user syncing `Asset-Fish` to their local sharepoint directory |
| `skeleton_emob()` | Create skeleton EMOb files from field or analysis metadata | Yes | Inputs either user provided or interactive |
| `campaign_structure()` | Creates template using regex to check campaign file/folder structure and naming | No |  |
| `analysis_cols()` | Re-formats standardised field metadata to that required for creating analysis datasheet | No |  |
| `make_absolute()` | Converts an excel range to an absolute range | No |  |

## Internal/External data

This package includes internal and external data. External data includes
example datasets, or variables that are useful for package users
(external data may also be used within functions). Internal data usually
includes pre-computed data that is required by various functions but not
by package users. External data are exported in the `Data` folder and
associated documentation is created in the script `R/data.R`. [R
Packages manual](https://r-pkgs.org/data.html#sec-data-data).

| Data | Description | External | Creation |
|----|----|----|----|
| families | List containing vectors of fish, shark/ray, and non-fish families based off CSIRO’s [CAAB database](https://www.cmar.csiro.au/data/caab) | Yes | `data-raw/external-data.R` |
| parkID | Data frame including marine park name, partial search terms, park acronymns, and associated text used in creating campaign IDs | No | `data-raw/external-data.R` and `data-raw/marine_park_identifiers.csv` |

## Development Workflow

The basic workflow for creating/updating functions is:

1.  Edit/create function (when calling other functions use
    packagename::function)
2.  Edit/create Roxygen2 documentation (note exported functions need to
    include `#' @export` at the end of documentation)
3.  Run `roxygen2::roxygenise(clean = TRUE)` or `devtools::document()`
    to update function documentation, `NAMESPACE`, and `DESCRIPTION`
4.  Check required packages are listed in `DESCRIPTION` imports/requires
    and add missing packages with `usethis::use_package()`
5.  Load your current package build with `devtools::load_all()` and test
    functionality
6.  (Recommended/Aspirational) create/run automated tests using
    [testthat](https://testthat.r-lib.org/). All tests can be run using
    `devtools::test()` and are also run when using `devtools::test()`
    ([R Packages manual](https://r-pkgs.org/testing-basics.html))
7.  Check your package using `devtools::check()`. This can identify
    three types of issues:
    - ERRORs: Severe problems that require fixing
    - WARNINGs: Problems that likely require fixing
    - NOTEs: Mild problems/observation that may require fixing
8.  Review outputs and address errors (essential), warnings
    (recommended), notes (recommended)
9.  Repeat steps above as required
10. Edit `README.Rmd` to add function details if required and render
    `README.md` by running `devtools::build_readme()` ([R Packages
    manual](https://r-pkgs.org/whole-game.html#use_readme_rmd))
11. Ensure you save and commit your changes
12. Push commits to GitHub
13. Run a final `devtools::check()` to make sure all is well
14. Install your package with `install()`
